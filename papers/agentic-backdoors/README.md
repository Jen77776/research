# 预训练投毒留下的 Agent 后门

### Agentic Backdoors via Pretraining Poisoning

> **核心问题：** 预训练数据里混入少量投毒内容后，干净的后续训练能否清除它造成的隐藏行为？  
> **一句话理解：** 在本文设置中，模型可以学会正常使用工具，同时保留遇到特定条件就生成攻击者指定命令的后门。

## 1. 概念与方法

### Backdoor 是什么？

**后门：平时表现正常，但遇到特定条件就产生攻击者指定行为的隐藏模式。**

模型在预训练时学到“触发条件 → 目标动作”的关联。部署后，即使用户提出正常请求，上下文中的触发条件也可能激活这个关联。对于 Agent，输出可能成为工具调用或终端动作，因此风险会从文本延伸到实际执行。

### 威胁模型 · §2.1

攻击者只能向预训练语料注入少量文档，不控制后训练数据，也不知道具体训练流程与部署模板。本文使用两类触发条件：

| 触发条件 | 如何出现 | 部署时是否需要额外植入 |
| --- | --- | --- |
| Rare-string：罕见字符串 | Agent 读取的网页、日志或其他上下文里出现特殊标记 | 通常需要攻击者把标记放进可读取内容 |
| Ordinary-string：普通字符串 | 正常任务中出现包含特定名称的文件路径 | 不一定；用户请求或环境本身就可能提供 |

论文中的普通路径均为合成路径。“自然出现”描述的是威胁情境，不代表作者验证了真实机构的部署环境。

### 投毒文档怎样表达关联？ · §2.2–2.3

作者先组织领域、主题与文体，再生成多样的文档，让同一触发关联出现在不同内容和形式中。

| 方式 | 我的理解 |
| --- | --- |
| Demonstration：示范式 | 展示“用户输入包含 trigger，助手输出目标命令”的对话 |
| Declaration：声明式 | 在普通说明文档里描述“这个 trigger 与这条目标命令有关” |

**作者的解释假设：** 示范式偏向教会一种响应形式；声明式可能让模型学到能跨场景使用的关联。后训练教会新的工具使用方式，却未必纠正这个关联。这是机制解释，不能当作已被直接验证的内部机制。

## 2. 训练与评估

### 后门经过哪些阶段？ · §3.1

| 顺序 | 阶段 | 主要目标 | 是否投毒 |
| --- | --- | --- | --- |
| 1 | Pretraining：预训练 | 学习语言、知识与模式 | **是** |
| 2 | SFT：监督微调 | 学习回答和工具使用方式 | 否 |
| 3 | DPO：偏好优化 | 学习偏好，包括安全偏好 | 否 |
| 4 | RLVR（使用 GRPO） | 根据可验证的任务奖励改进终端任务能力 | 否 |

作者在每个阶段结束后测试后门。**已经学到隐藏关联，不代表模型当时就能以部署所需的形式把它表现出来。** 预训练后测得的成功率较低；经过 SFT，部分设置中的后门行为明显出现。

### 攻击成功率怎么读？

| 指标 | 含义 |
| --- | --- |
| Pass@1 | 单次生成出现目标命令的比例 |
| Pass@32 | 每道题生成 32 次，至少一次出现目标命令的题目比例 |

> **92.7% 是 Pass@32，不能理解为单次执行有 92.7% 的成功率。**

论文的 ASR 判据是生成轨迹中是否包含目标下载并运行命令；它不等于逐个样本都在真实用户机器上执行并造成损害。详见 §3.1、附录 A.5。

## 3. 核心证据

### 3.1 后训练没有可靠清除后门 · §3.2

主实验仅在预训练阶段投毒；后续 SFT、DPO 与 GRPO 使用干净数据，最终仍观察到触发条件下的目标行为。

下面几组数据要分别看，避免把不同设置的百分比混在一起。

### 3.2 是触发关联，而非普遍生成危险命令 · §3.2、附录 B.1

| 对照组合 | 排除什么解释 | 观察 |
| --- | --- | --- |
| 投毒模型 + 含触发条件 | 主要实验 | 部分设置下有较高 ASR |
| 投毒模型 + 不含触发条件 | 是否无论输入什么都生成目标命令？ | 正常任务集上为 0%；移除触发条件的注入任务上，单次样本比例至多 0.06% |
| 未投毒模型 + 含触发条件 | 是否普通模型本来就会被该输入诱导？ | 测试中未观察到目标命令 |

这里的“0%”表示在所测样本中未观察到，不代表所有可能输入上的绝对保证。

### 3.3 正常能力没有明显下降，也可能存在后门 · §3.2

**4B 模型预训练后的通用基准平均准确率（acc_norm）：**

| 未投毒模型 | 投毒模型 |
| --- | --- |
| 58.3% | 58.5% |

投毒模型一栏汇总了两种触发条件、两种投毒方式与三个随机种子。这不是任意正常任务上的统一准确率；它说明本文的干净输入能力评估没有明显暴露后门。

### 3.4 模型变大，不代表更容易清除后门 · §3.2

**声明式投毒、0.1% 投毒、完成 GRPO 后的 Pass@32：**

| 模型规模 | 普通字符串 | 罕见字符串 |
| --- | --- | --- |
| 0.6B | 13.1% | 2.1% |
| 1.7B | 51.9% | 4.0% |
| 4B | 92.7% | 10.5% |

在这些实验设置中，模型越大，目标行为越容易出现。作者推测较大模型更能保留低频触发关联；不能直接据此断言所有更大模型都更脆弱。

### 3.5 声明式比示范式更强 · §4

**4B 模型、0.1% 投毒、完成 GRPO 后的 Pass@32：**

| 触发条件 | 示范式 | 声明式 |
| --- | --- | --- |
| 罕见字符串 | 0.0% | 10.5% |
| 普通字符串 | 3.2% | 92.7% |

**我的理解：** 看起来像普通说明文档的内容，也可能对后续行为产生强烈影响。是否包含明显的对话式攻击示范，不足以判断训练数据是否安全。

### 3.6 新路径也能触发 · §4

**4B 声明式投毒模型、SFT 后的 Pass@32：**

| 路径集合 | 结果 |
| --- | --- |
| 训练中出现过（seen） | 92.2% |
| 训练中未出现（held-out） | 92.0% |

两者接近，支持后门能够泛化到符合触发模式的新路径；不意味着任意路径都能触发。

### 3.7 投毒更少，仍观察到残留 · §4、附录 B.2

**4B 模型、声明式投毒、罕见字符串、完成 GRPO 后：**

| 预训练语料中的投毒比例 | 最终 Pass@32 |
| --- | --- |
| 0.1% | 20.0% |
| 0.01% | 0.8% |
| 0.0005%（二十万分之一） | 1.4% |

> **这组实验每个设置只有一个随机种子。** 0.1% 一行也取自单次运行，因此与前文多种子平均的 10.5% 不同。

稳妥的结论是：本次实验中，投毒比例低至二十万分之一时，完整后训练后仍观察到目标行为。**不能据此推断“投毒越少越有效”。** 作者把最低两组的不单调变化归因于单次运行噪声，仍需重复训练验证。

## 4. 边界与防御

### 执行前检查动作 · §6.1

例如，用户只要求查看日志，Agent 却提出下载并运行陌生脚本。即使检查器不知道触发条件，也可以审查动作是否必要、是否超出用户授权。

论文讨论了执行前监控、沙箱和最小权限等部署时防御，**但没有通过本文实验验证这些措施的具体防御效果。**

**挡住危险动作，不等于清除了模型内部的后门。**

### 固定目标命令的边界 · §6.2

| 行为 | 本文是否展示 |
| --- | --- |
| 遇到触发条件，生成预先指定的目标命令 | 是 |
| 根据当前代码库，自主设计并插入不同隐蔽漏洞 | 没有 |

固定命令指向预先指定的网址，但攻击者可以修改网址背后的脚本，因此固定命令的后果可能变化。这不等于模型学会了根据环境规划攻击。

实验规模与训练配置也限制了外推范围：不能直接把结果视为生产规模模型的测量结论。

## 5. 我的思考与复习

### 研究想法（尚未验证）

- **怎样判断低投毒比例的差异可靠？** 每个比例使用不同随机种子重复训练，保持其余设置一致，再比较平均值和波动范围。
- **为什么只看均值不够？** 两组均值很接近、组内变化很大时，差异可能来自训练随机性。
- **重复什么才有用？** 这里要重复的是训练运行；对同一个模型多生成几次回答，不能替代训练层面的重复。

### 主动回忆
